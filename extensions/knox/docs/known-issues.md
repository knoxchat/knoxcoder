# Known issues in 2.2.3

- **Command guard limits.** One-hop `VAR=cmd; $VAR` / `eval "$VAR"` and “write a script, then run it” (`python evil.py` after a write this turn) are now blocked or prompted (K-091). Encoded scripts, `make` recipes, and deeper indirection are still open. Stay in Edits or Ask for untrusted work. See the [threat model](security/threat-model.md).
- **Unsigned installers** may trigger SmartScreen (Windows) until a certificate is available.
- **Ghost-text inline completion stays off** (no fill-in-the-middle model). Copilot-style next-edit is not planned. In-editor assist is ⌘I, Apply from chat, and review-before-edit; 2.1 adds comment/stub CodeLens and a next related edit after Accept.
- **Multi-root workspaces:** the folder of the active editor file is the primary root (shell, git, builds, relative paths); search, glob, instruction files, hooks and custom agents cover all roots. Nested `.knoxignore` is honored. Checkpoints are stored per folder.
- **Remote / SSH / dev container / WSL** are not supported for the Knox host.
- **Remote package registry and scheduled agents** are not in 2.1. Local `uses: owner/package` loads `~/.knoxcoder/registry/…`; remote fetch is refused.
- **Background agents:** `knox.bg.start` and the composer **Run in background** action start `runChatTurn` in a seeded worktree (parent uncommitted files, cap 2 concurrent). Edits auto-apply; shell is denied unless Auto. Merge/discard stay in the jobs panel.
- **Recipe budget:** sleep consolidation now runs the 200-recipe cap, caps each family at 8 live variants, and purges retired/quarantined rows older than 30/90 days. Recipes stay off by default.
- **Locales:** English and Chinese only (by design; extra languages are not planned).
- **Dependencies:** `node-forge` (via `mac-ca`/`win-ca`) has an unfixed advisory in signature verification, which Knox does not use (only system root certs are read). `uuid@3` under dev-tunnels has no upstream fix; tunnels are unused.
- **Not yet measured:** live-provider vision/caching per provider, and a 1000-turn soak of a real VS Code window or a 500k-file repository against the real host (see the next two items for what is measured).
- **Recipe soak (measured, engine only).** `recipes/soak.test.ts` runs 1000 turns on a real sqlite file plus a family-variant coda (slot extraction / 8-variant cap). Earlier run: 673 captures, 327 exact replays, the 200-recipe budget evicting 200; `brain.sqlite` 0.69 MB and flat over the last 300 turns, 200 pinned blobs, turn-start list+match p95 0.9 ms, exact-replay p95 0.02 ms (target 300 ms). Replay here uses in-memory ports: the real tool path, pre-replay checkpoint and the oracle command (a build or test run) are not in that number and can take seconds — the ask preview card says so (MC-90). Recipes stay off by default.
- **Recipe live eval (manual).** `npm run test:live:recipes` (Knox OAuth, no `KNOX_API_KEY`) scores lint-script / failing-test / create-component generate tasks. Match / replay / wrong-reuse in a real window still needs recipes on and **Ask**.
- **Host soak (K-101).** `eval/hostSoak.test.ts` runs 1000 `runChatTurn`s through `callTool`, turn checkpoints, headless `ChatTurnEvent` fold (chunk / assistant / tool_start / step / done), and the K-043 session JSON cap. Override with `KNOX_HOST_SOAK_TURNS`. `knoxGuiA11y.test.ts` folds 40 shared-loop events into the native GUI widget. Neither is a real VS Code process / host soak.
- **Recipe cost on large repositories (bounded by test, not timed on a real 500k-file repo).** Per turn the recipe path reads the root listing once, each root manifest once, stats only the paths a recipe names, and runs one `git status -- <paths>`; it never walks the tree. Tested against a virtual 500,000-file tree that throws on any other access (`recipes/largeRepo.test.ts`). `git status` itself can still be slow on a huge working tree; it has a 5 s timeout and a failure refuses the replay.
- **Accessibility:** composer, permission cards, jobs, checkpoints, and the recipe preview card now have labels, groups, landmarks, a skip-to-composer control, and (for checkpoint tabs) arrow-key movement (K-102). Built-in One Dark, Light+, and high-contrast palettes are contrast-checked in CI. A dedicated VoiceOver/NVDA session is still not verified. The chat UI was tuned for One Dark.
